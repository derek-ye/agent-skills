## Dispatch and follow through

Before dispatch, record each outcome, relevant source/session IDs, bounded scope, dependencies, expected artifact, acceptance criteria, allowed actions and stopping point. Give each agent only the relevant context. Choose research versus implementation deliberately: a mostly delivered cleanup task may need a closure assessment rather than code.

Use isolated working areas for concurrent code changes and preserve unfinished work. Parallelize independent work that advances the user's priorities; serialize shared-file integration and dependent changes. Do not create new user-owned Codex tasks unless Derek requests them.

Inspect returned artifacts and relevant diffs, check evidence at the actual resulting revision, and send agents concrete corrections when acceptance is unmet. Reuse prior valid reviews; inspect changes since their reviewed revision instead of automatically repeating whole reviews. Stop repeating checks once the relevant acceptance is established.

## Completion and handoff

For each item, report the deliverable and location, what was verified and how, remaining limits/dependencies, and the exact next action and owner. Keep implementation readiness, publication, review approval, design QA, deployment and observed production acceptance distinct. Never mark an outcome done merely because an agent finished or tests passed.

For journal work, update the note only with evidenced completion or a concise useful next action, preserving its formatting and unrelated user edits. Use the available weekly-todo skill when changing the note. Keep session tracking and coordination prose in a separate local run record. If unfinished work survives the run, save the agent/session or workspace reference, remaining acceptance and next checkpoint; do not promise background monitoring unless it is actually configured and authorized.
